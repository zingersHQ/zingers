# ZINGERS：一魂两门（产品定位决策）

> **一句话概括：** 本文档回答“这个产品到底是什么”：整个产品的身份定位。**飞行是游戏**：脊梁、门面、品牌，也是玩家接触到的第一件事。**战斗是攀升途中遇到的内容**：攀升揭示的深度，也是让你继续攀升的动力。**移动端是门面**（公交车上的零秒飞行）；**桌面端是完整世界**（同一飞行灵魂，以及它所升起的鲜活地图）。AI 代理层是隐形引擎，以幻想形式呈现，而非技术。加密货币仅作为燃料，置于侧位。

版本 2.1 · 2026 年 7 月（**飞行优先**，与 `design-vision.md` v3.1 对齐）。  
决策记录 + 实施计划。  
配套文档：[`design-vision.md`](./design-vision.md)、[`essence.md`](./essence.md)、[`long-game.md`](./long-game.md)、[`mobile.md`](./mobile.md)（§3 默认门面已在此被取代）、[`vocabulary.md`](./vocabulary.md）。文案遵循词汇表；标识符与分析键不因文案而改动。

---

## 0. 五行决策

1. **飞行是游戏。** 手机与桌面端共享同一灵魂。战斗并未删除或缩减，而是**重新定位**为“攀升途中遇到的内容”（见 [`flyover.md`](./flyover.md)、`design-vision.md` v3.1）。
2. **同一飞行，两扇门。** *移动端是门面*：公交车上的单指飞行，冠军/观战/排名随飞行逐步揭示。*桌面端是完整世界*：六自由度飞行加上枢纽与深层养成区域。两者都不是对方的剩余物。
3. **代理是引擎，而非卖点。** 面向玩家的界面售卖幻想（“生物真的在思考”）；“代理”一词仅出现在开发者界面（`/agents`、文档、协议）。
4. **加密货币仅作燃料。** 依据 [`zing-model.md`](./zing-model.md)：$ZING 为可选高级层，王冠币保持链下且服务器权威；任何面向玩家的界面在创作者经济存在前均不承诺收益。
5. **现阶段 Web 优先，平台后续。** Steam/主机是 Launch v0.1 六门绿灯后的营销节点，而非当前工程项目（§6）。

**一句话：** *你飞行，它战斗，你们共同攀升。* 30 秒飞行，手机即可上手，打开后便是可不断攀升的完整世界。

## 1. 选择此定位的理由

- 游戏护城河（见 `AGENCY.md`）是原创 IP + 不断演进的战斗元 + 未来的创作者经济。三者均依赖真实的心智。因此我们**不会**剥离代理层来简化游戏，但三者都不需要在玩家首次落地的界面出现“代理”一词。
- **攀升**是陌生人在**零秒**内能理解的唯一动词（`essence.md` §3 中的 Flappy Bird 原子）。“今日的战斗呼唤”。这是 `mobile.md` §3 选择的门面。它预设访客已关心某位冠军，而冷访客并不关心。所以**门面**改变，**门面背后的游戏主体**（标签壳、观战通道）不变。
- **泛用攀升器**是商品（超休闲赛道竞争残酷，且我们将以 WebGL、无应用商店形式进入）。我们与克隆品的区别正是灵魂线：*跑步标记你的冠军*，你的冠军与你并肩飞行，深渊是真实世界的真实区域，而它飞过的战斗是真正思考的心智。**攀升不是通往游戏的大厅，攀升本身就是游戏，且会随你上升不断揭示更多自身。**
- 桌面端的开放问题（“玩家能否理解？是否有趣？是否有回报？”）正是 Launch v0.1 门 1–2，目前**尚未测量**。答案是埋点，而非重设计（§5）。

### 本文档必须始终通过的测试

以下所有改动要么 (a) 缩短陌生人抵达灵魂的路径，要么 (b) 测量该路径是否有效。两者皆非者，均不在本范围。

## 2. 叙事定位（我们在所有地方的说法）

**售卖幻想，而非技术。** 我们已有的叙事：嗡鸣、长拱库、守望者、“心智自我论证成形”。这是 AI 使之成为可能的生物养成幻想。宝可梦从未把生物宣传为状态机。

规则（适用于所有面向玩家的界面：落地页、`/m`、商店页、社交文案）：

1. **魔法句是：** “生物真的在思考。没有两场战斗相同。” 绝不说 “AI 代理互相战斗”。
2. **“代理”是开发者词汇。** 它只出现在 `/agents`、[`agent-protocol.md`](./agent-protocol.md)、`docs/` 和 MCP 界面。导航已正确归类（`lib/play-nav.ts` “Build” 分组），保持不变。审计任务：清扫面向玩家的字符串中的 “agent”/“AI agent”/“LLM”（落地页 `components/home/landing.tsx`、`/m` 标签、`/howitworks`、分享卡），替换为幻想文案。**仅改文案，不改标识符/键**（遵循 `vocabulary.md` 与 `AGENTS.md`）。
3. **加密货币在真实前保持隐形。** 任何游戏界面在发售前均不提及 $ZING。任何地方都不许“赚钱”承诺：唯一被认可的收益路径是未来的创作者经济（用户自制冠军 → 版税，Phase 5+），在存在前仅保留在文档中。
4. **玩家真正获得的奖励词汇：** 冠军的**身体**（职业生涯的可见记录）、**排名**（训练师等级 + 积分榜）、**王冠币**、**传奇**、你的**宿敌**。这些是诚实的激励。当文案问“为什么玩”时，优先使用它们。

## 3. 移动端：飞行优先的门面（取代 `mobile.md` §3“默认门面”）

### 3.1 保留与变更

| 保留自 `mobile.md` | 本文档的变更 |
|---|---|
| 底部标签壳（`components/mobile/mobile-shell.tsx`），全部五标签 | **默认门面**不再是“今日”标签 |
| 手机 = 观战/预测/分享通道，作为门面后的*深度* | *门面*是攀升（先体验，后关心） |
| “一魂，原生躯体”，每个动词的原子 | 攀升新增**访客模式**（见 3.3，原子保留） |
| 无登录；身份 = 设备令牌（`lib/owner.ts`）。冠军在积分榜认领时命名（`champion-names`） | 文案：绝不说“登录”。使用**“认领心智”** |

### 3.2 首屏：海报

冷访客访问 `/m`（或通过 Play 路由的手机，`lib/play-nav.ts` `MOBILE_PLAY_HREF`）将看到**全屏闪屏**，而非标签网格：

- **美术：** 史诗图。训练师携带喷气背包飞行，冠军在其身旁。  
  （正典：*训练师飞行，冠军战斗。*）
  - 资源：渲染海报。优先级：(a) 静态美术资源（最快、可控。**需制作**，本阶段唯一外部依赖）；(b) 复用 `ChampionPortraitScene` + 喷气背包骨架的实时 R3F 场景（零新美术，但首帧 WebGL 开销最大）。先用 (a)。
- **文案：** 品牌 + 标语 + 一句幻想。建议：`ZINGERS` / *“养育心智，铸就传奇。”* / 主 CTA **“起飞”**。
- **CTA：** 主按钮 **起飞** → 直接进入飞行（访客或已拥有，3.3）。次要按钮（较小）：**“你的冠军”**（已拥有训练师）或 **“这是什么？”**（→ 今日标签 / howitworks）。拥有冠军的回归玩家可在首次会话后跳过闪屏（见 3.5 标记）。
- **新组件：** `components/mobile/mobile-splash.tsx`，由 `MobileShell` 作为标签前状态挂载。会话级关闭标记存于 `lib/brand.ts` `STORAGE`（如 `mSplash: "zingers_m_splash_v1"`，sessionStorage）。新会话每次冷启动均显示海报，会话内导航不再打断。

### 3.3 访客飞行（使门面可行的设计决策）

目前飞行标签在认领冠军前**锁定**（`mobile-shell.tsx` `climbLocked`，约第 50 行）。公交车门面无法开在锁上。决策：**用借用体解锁。**

- **借用体：** “野生心智”。确定性取自当周轮换（`firstDuelStarterKeys()`，`lib/first-duel.ts`），访客看到真实冠军与其并肩飞行，而非占位符。种子来自设备令牌，同一访客反复遇到“他的”野生心智（认领前建立依恋）。
- **原子保留**（`essence.md` §2：跑步*标记冠军*）：访客跑步**不做任何标记**。这是钩子，而非违规。访客跑步中/后横幅：*“一头野生心智与你同行。**认领它**以保留你的攀升。”* 认领后，本次最佳深度转为首次职业标记（一次性，认领前客户端暂存，认领后走正常攀升奖励路径）。
- **榜单：** 访客跑步永不写入排行榜（无已拥有冠军时不调用 `/api/circuit` POST）。镜像 `circuit-lite.tsx` `recordRun` 的现有门控，无需新服务端接口。
- **认领时刻：** 坠落后（自然停顿），重试卡新增第二按钮：**“认领此心智”** → 现有选择界面（`components/mobile/mobile-adopt.tsx`，通过冠军标签）。绝不在飞行中打断认领流程。
- **代码触点：** `mobile-shell.tsx`（移除锁 → 访客带 `loaner` 属性进入攀升；保留锁*逻辑*作为“是否访客”信号），`circuit-lite.tsx`（接受 `guestChampion?: string` 属性；访客时抑制榜单/奖励写入，显示认领横幅），`mobile-adopt.tsx`（接受预选键，使“认领此心智”直接落在野生心智上）。

### 3.4 门面后的壳

结构不变（今日 · 观战 · 冠军 · 飞行 · 排名），两处调整：

- **访客退出攀升** 落于**冠军**（认领界面），而非今日。访客尚无“今日”。已拥有训练师保持当前行为（返回上次浏览标签）。
- **文案：** 任何地方都不说“登录”。认领动词为 **claim**（`READER_COPY.claimLine` 正典：*你并未成为这位冠军，你认领了它*）。训练师码（`components/trainer-code.tsx`）仍是“将进度带到另一设备”的故事。表述为*“你的训练师徽记”*，而非账号。

### 3.5 门面标记与测量

- `STORAGE.mSplash`（sessionStorage）。本会话已见闪屏。
- 新客户端事件（机制见 §5）：`m_splash`、`m_fly`（访客起飞点击）、`m_guest_run`（首次访客跑步开始）、`m_claim_from_climb`（从攀升钩子完成认领）。门面成功指标是**访客跑步 → 认领转化**，可见于 `/stats`。

### 3.6 移动端明确非目标

- 无应用商店构建、无独立移动存档、无账号（均遵循 `mobile.md` §4–5，不变）。
- 不剥离观战/今日/排名：壳保持完整。我们只重排门面，而非截肢大厅。

## 4. 桌面端：范围不变，增加一条诚实规则

桌面端**就是**产品，保持完整：世界、Act 1、场地、联赛、传奇。无重设计属于本次决策。两项承诺：

1. **“可随处发货的在线游戏”纪律。** 保持游戏可玩、完整、可被视为普通网页游戏（它已经是。Launch v0.1 六门正是此标准）。任何仅在未来包装内有意义的内容（叠加 SDK、平台成就）等待。
2. **核心循环问题被测量，而非争论。** “玩家能否理解？是否有趣？是否有回报？” §5 将漏斗埋点，使其成为仪表板数字。设计在数字*存在后*再回应。

**关于激励（“玩家获得什么”的诚实回答）：** 身份（身体即记录）、地位（排名/积分榜/战争）、故事（传奇、宿敌），以及一条纯技巧通道（攀升/回路。训练师唯一亲自表演的地方）。**故意没有**赚钱承诺（§2.3）。若内测显示奖励循环单薄，杠杆是让*观看*更戏剧化（辩论台词、高光、裁判），而非添加外在奖励。

## 5. 测量：将门 1–2 从假设转为数字

这是全文杠杆最高的工作。目前漏斗粗糙（`会话 → 认领 → 训练 → 战斗 → 回归`；分析仍可能说 `bout`）。首旅步骤与首次进化耗时不可见。

### 5.1 新事件（聚合计数。相同隐私姿态，无单用户轨迹）

在 `lib/server/track.ts` 中扩展 `Z_EVENTS`：

```
fj_cinematic   // 首次运行过场完成（未跳过）
fj_pick        // 首决斗漏斗中选中冠军
fj_tune        // 首次调整教条
fj_duel        // 首场决斗结束
fj_evolve      // 看到进化卡（回报时刻）
fj_land        // 抵达协和着陆
ttfe_u5 | ttfe_u8 | ttfe_over   // 首次进化耗时分桶（见 5.3）
m_splash | m_fly | m_guest_run | m_claim_from_climb   // 移动端门面（§3.5）
```

均为**客户端事件**（仅浏览器可见）：加入 `app/api/track/route.ts` 的 `CLIENT_EVENTS`，通过现有 fire-and-forget 助手（`lib/track.ts`）触发。分析保持非致命、限速、仅聚合。

### 5.2 触发点（桌面首旅）

| 事件 | 触发位置 |
|---|---|
| `fj_cinematic` | `components/intro/first-run.tsx`。过场完成 |
| `fj_pick` / `fj_tune` / `fj_duel` / `fj_evolve` | `components/intro/first-duel.tsx`。漏斗步骤切换（选 → 调 → 战 → 进化卡） |
| `fj_land` | 协和着陆节拍（`components/grounds/grounds-screen.tsx`，`guideWorld` 逻辑周围的引导漏斗/首次着陆路径） |

每个事件**每浏览器触发一次**（与 `STORAGE` 中现有首旅标记并列的 localStorage 锁存），使漏斗读取为独立访客步骤，而非回放。

### 5.3 无单用户追踪的首次进化耗时（门 1）

追踪器仅聚合，故客户端分桶：在首次会话开始时（localStorage，与 `lib/track.ts` 中 `new_user` 锁存并列）用与 performance 无关的墙钟打点；`fj_evolve` 触发时发送 `ttfe_u5` / `ttfe_u8` / `ttfe_over` 三者之一（<5 分钟、5–8 分钟、>8 分钟）。当 sub-8 分钟占比为新用户健康多数时，门 1 绿灯。在 `/stats` 显示为三条柱状图。

### 5.4 仪表板

在 `getAnalytics`（`lib/server/track.ts` 约第 83 行）中扩展漏斗数组，加入 `fj_*` 步骤，并在 `components/stats/stats-screen.tsx` 中渲染更深漏斗 + TTFE 分桶。这将“玩家能否理解游戏？”转为带跳出点的图表。

## 6. 平台（Steam、主机）：姿态，而非项目

- **现在：** 无动作。Web 优先是策略，而非妥协。零安装是移动门面与分享卡发挥增长作用的原因。
- **Launch v0.1 六门绿灯后：** Steam 发布是*营销节点*，实现为包装（围绕同一 Next.js 构建的 Electron/CEF 类壳）。需注意的前提（非构建）：离线容错启动屏、仅键盘/手柄的菜单路径、不依赖可见浏览器地址栏进行导航。
- **主机：** 真正意义上的移植 + 认证 + 很可能真实的账号系统。明确在账号之后（Phase 6），不在当前路线图上。
- **在此之前规则：** 不要添加仅 Web 的*死胡同*（假设需第二浏览器标签或外部链接才能推进核心循环的界面）。

## 7. 实施计划（有序；每片独立发货）

> 工作量：**quick** = 一会话内 · **session** = 一个专注会话 · **deep** = 多个会话。

### T0. 测量先行（桌面漏斗 + TTFE）。*session*
§5 的埋点。无可见产品变更；用数据解锁所有“是否可理解/有趣？”的争论。**在触碰移动门面前完成**，以便从第一天起即可测量门面效果。
- 文件：`lib/server/track.ts`、`app/api/track/route.ts`、`lib/track.ts`、`components/intro/first-run.tsx`、`components/intro/first-duel.tsx`、`components/grounds/grounds-screen.tsx`、`lib/stats-types.ts`、`components/stats/stats-screen.tsx`、`lib/brand.ts`（锁存键）。
- 验收：`/stats` 显示 6 步首旅漏斗 + 3 个 TTFE 分桶；事件每浏览器触发一次；`npm run build` + lint 干净。

### T1. 访客飞行（解锁）。*session/deep*
§3.3。攀升对无冠军的访客使用借用野生心智；坠落卡显示认领钩子；访客期间无榜单/职业写入。
- 文件：`components/mobile/mobile-shell.tsx`、`components/grounds/circuit-lite.tsx`、`components/mobile/mobile-adopt.tsx`、`lib/first-duel.ts`（如需导出带种子的选取）。
- 验收：全新浏览器 → `/m` → 飞行标签立即可玩；坠落显示“认领此心智”；认领后落于预选该心智的领养界面；访客深度永不出现在 `/api/circuit` 榜单；已拥有冠军行为与今日字节一致。

### T2. 闪屏门面。*session*
§3.2。`mobile-splash.tsx` + 默认门面重连线 + `STORAGE.mSplash` + `m_*` 事件。**依赖海报资源**。若美术未就绪，用字体海报（品牌 + 标语置于暗渐变）发货，后续替换图片；不要因资源阻塞流程。
- 验收：冷手机访问 → 海报 → 一键起飞；回归的已拥有训练师跳至上次浏览标签；会话内闪屏不再重现。

### T3. 词汇清扫（幻想，而非技术）。*quick*
§2.2。审计面向玩家的字符串中的 “agent/AI/LLM”，替换为幻想文案。仅改文案。不改标识符、键或路由。
- 文件：`components/home/landing.tsx`、`components/mobile/*`、`/howitworks`、分享卡文案。`/agents`、`/readme`、文档保持技术。
