# ロングゲーム：Zingers が 40 分で終わる理由とその止め方

> **ステータス：Stage 0–6 リリース済み（2026 年 7 月）。**  
> デザイン聖典の補足資料。  
> プレイヤー向け Flight フィクションは [`bible/10-ascent.md`](./bible/10-ascent.md) を参照。  
> 用語は [`vocabulary.md`](./vocabulary.md) を参照。  
> 関連資料：[`design-vision.md`](./design-vision.md)、[`essence.md`](./essence.md)、[`flight-first-plan.md`](./flight-first-plan.md)。

本資料が答える問い：**プレイヤーはどれだけ遊べるのか、そして何を改善すればいいのか？**  
以降の Stage は特記がない限りライブ。

---

## 1. 素直な時計

現行ビルドにおけるコールドプレイヤーの推定値：

| 窓口 | 時間 | 終わるきっかけ |
|------|------|----------------|
| 初回セッション | **35–45 分** | Flight → 獲得 → 1 戦 → 「……で、次は？」 |
| 2 日目 | **約 8 分** | デイリー、1 回の Flight、終了 |
| 4 日目 | **約 0 分** | 戻る理由が何も提示されていない |
| Flight に没入した少数派 | **週 3–5 時間** | 本物のハイスコア欲求（感触が刺さった場合） |

薄いゲームのように見えるが、そうではない。§2 参照。  
これは **可視化不足** の問題だ。コンテンツは存在するのに、プレイヤーがその存在に気づかない。

## 2. 実際に作られているもの（サプライズ）

ドキュメントではなく、ライブコードを監査した結果：

- **Flight**：10 の Reach にまたがる 100 セクター、ハザード、キャンプ、ファーストライト宝箱、Crown キャッシュ、スカウト、ゴースト、共有リンク、2500 Crown の Hundred 賞金。  
  (`components/grounds/climb/*`, `lib/climb-campaign.ts`)
- **Champion**：First Minds + 焼き込み図鑑（Stage 6 wave 1）、タイプ五角形、5 ティア、キャリア由来のボディ＋表現型、Saga 台帳、インプリント。  
  (`lib/engine/roster.ts`, `lib/minds/baked.ts`, `lib/imprints.ts`, `lib/evolve/*`)
- **リターンフック**：デイリー戦、デイリーキャッシュ、シーズン目標、28 日シーズン、クラン戦争、予測ストリーク、cron で自己対戦するグローバルランキングボード、Director ガイド、アンロックトラック、ウィング特性、Conditions、Expedition。

これらは **最初の 30 分で 15 時間分のコンテンツが提供されている** 状態であり、ほとんど見えないままになっている。問題は量ではなかった。

## 3. 診断。4 つの構造的欠陥

1. **次に何をすべきかを指し示すものが一切ない**。  
   「今何をすればいい？」に答える関数がどこにも存在せず、すべてのフックは「すでに知っている人だけ」が発見できる。
2. **最初からすべてが解放されている**。  
   全リージョン、全シナリオ、全 100 セクター、全 8 人のリクルート。15 時間の解放が一瞬で消費される。長く感じるゲームは大抵「良いものを後回し」にしている。
3. **育成がプレイする動詞に可視的な影響を与えない**。  
   トレーニングに 60 Crown かけたところで、3 つの見えないダイヤルが動くだけ。プレイヤーは自分の育てた成果がランや戦いに反映されていると実感できない。
4. **繰り返す動詞にバリエーションがない**。  
   どのランも同じラン、どの戦いも同じ戦い（ただし文章は違う）。

## 4. ものさし（Pokémon と比較しない）

Pokémon や Zelda は **コンテンツ量** で勝負するゲームだ。数百人で手作業で作った世界。  
我々はそのレースに永遠に勝てないし、比較しても絶望しか生まない。

本当の競合は **Balatro**（1 つのカードゲーム、約 150 の修飾子、数百時間）、**Vampire Survivors**（1 つのメカニクス＋アンロックツリー）、**Football Manager**（世界自体はほぼなく、純粋なキャリア摩擦）だ。  
3 つに共通するのは、Zingers がすでに持っているアセットのほんの一部から膨大なプレイ時間を引き出している点で、その手段は **ラン変動、アンロックの段階的解放、結果を伴うキャリア状態** の 3 つ。

**目標**：初月で 10–15 時間、1 日 8–12 分の本当の理由を持って開いてもらう。Zelda ではない。  
新しいアートなしで、今の 5〜10 倍に到達可能。

## 5. 方向性の決定（創業者判断、2026 年 7 月）

> **Flight がゲーム。Champion はセーブデータ。Battle は句読点。**

LLM の議論トランスクリプトを読むのは、繰り返せばすぐに陳腐化する。  
深みはプレイヤーの手が触れる場所、つまり Flight に置くべきだ。これは Champion を捨てる話ではない。**因果関係の逆転** である。

| | 現在 | 変更後 |
|---|---|---|
| Flight → Champion | 深みがシギルを刻む | 変更なし（維持） |
| Champion → Flight | **何も起きない** | 飛ばすマインドが **Flight の遊び方を変える** |

Champion を育てる行為が、プレイヤーが実際に操作する動詞に対するビルドシステムになる。  
ハンドリング、スカウト範囲、セカンドライフ、ゴールド引き寄せ、ハザード読み……。「マインドを育てる」はサイドタブではなく、育てる理由そのものになる。  
それは Pokémon 的な感覚（チームビルディング、意味のある選択、結果の可視化）を、正しい動詞に移したものだ。

Battle は残す。「飛んで、戦う」という差別化点と、非同期リーグはプレイヤーが寝ている間に進行するコンテンツとして有効。ただし **解決済み・一目でわかる・賭けのある瞬間** に圧縮する。テキストの壁を読ませることはしない。

## 6. 計画

労力対効果順。各 Stage は単独でリリース可能。

### Stage 0. Director *(1–2 日)* ✅ リリース済み

既存のセーブ状態に対する純粋関数で、「今何をすべきか」を 1 行と 1 ボタンで答える。  
プレイヤーが着地するすべての画面に表示。新規コンテンツは作らず、すでに存在するコンテンツを可視化する。  
`lib/director.ts` + `components/director/*`。

### Stage 1. アンロックトラック *(3–5 日)* ✅ リリース済み

すべての活動が寄与する 1 本のトレーナートラック。各ランクで **名前付き** の何かが解放される：  
Reach のブロック解放、トリビューナル、ガントレット、ブローカー、第 2 リージョン、リクルート枠、スカウト。  
新規コンテンツではなく、既存コンテンツの配給。15 時間の解放を再構成し、Director に指し示す脊椎を与える。

ライブモジュール：`lib/unlock-ladder.ts`。  
Flight 天井（モバイル＋デスクトップ）、ハブゲート、ブローカー、スカウト、リクルート枠に適用。Director は次の名前付き扉を優先的に指し示す。  
Reach II の証明ゲートは変更なし。すでに飛んだ深さは grandfathered され、既存セーブはソフトロックされない。

### Stage 2. Champion → Flight の因果関係 *(1–2 週間)* ✅ v1 リリース済み

§5 の核心。各 Champion が **ウィング特性** を付与し、ランに数値的に影響を与える。  
インプリントとマイルストーンで新しい特性を習得し、プレイヤーは発進前にロードアウトを選択。  
8 体のマインドが 8 種類のロードアウト空間になり、すべての育成行動が実際に操作する動詞に還元される。

ライブモジュール：`lib/wing-traits.ts`。  
Force タイプごとに 1 つの **innate** 特性＋最大 1 つの **earned** 特性（軸／キャンプ／気質）。  
効果：ライフ、ゴールド確率、グライド、スタンブル、スカウトキャンプボーナス、巡航速度。  
`ascentSessionMods` で両方の Flight ボディに適用。レディストリップに `WINGS · …` と獲得済みトグルを表示。

### Stage 3. Conditions *(3–5 日)* ✅ v1 Flight リリース済み

ランまたは戦いに適用されるデータ駆動の修飾子：薄い空気、霧、横風、ライフ 1、ゴールド 2 倍、スカウトなし、敵対的観衆、サドンデスなど。  
20 以上は 1 日程度のライティングとエンジンフックで済み、既存のすべてのサーフェスを乗算的に拡張する。  
現時点で最も純粋なパラメトリック勝利。

ライブモジュール：`lib/conditions.ts`。  
UTC 日ローテーションで 13 のランク付きデイリースカイ、ウィング特性の後に `mergeRunMods` で統合。  
スカウト練習は Clear Sky のまま。レディストリップに `TODAY · …` を表示。Director もスカイを also-ask として提示可能。  
戦い側の Conditions は保留。

### Stage 4. キャリア摩擦とレガシー ✅

ライブモジュール：`lib/career-friction.ts`、`lib/legacy.ts`。  
フォーム／疲労／傷痕がウィング＋Conditions の後に Flight に積み重なる（Climb + Circuit に `applyCareerToMods`）。  
ライバル章は `maybeEscalateRival` / `currentRival` でエスカレート。  
引退すると伝説が封印され、次の獲得時に heirloom ウィングが Long Vault に待機（`retireOwned`）。  
Director は消費済み／壊れた厩舎をローテーションし、Face／引退を also-ask として提示。

### Stage 5. Expeditions ✅

ライブモジュール：`lib/expeditions.ts` + `lib/server/expedition.ts` + `/api/expedition`。  
UTC 週ルート：シード（`climbSector(i, seed)` でレイアウト生成）、1 つの Condition、20 セクター、ボディごとの専用ボード。  
Climb + Circuit に `expedition` モード。キャンプなし、XP／Crown は少なめ。  
レディストリップに `WEEK · …` を表示。Director も also-ask として提示。  
#1 のゴーストは保留（`lib/climb-ghost.ts` にコーデック準備済み）。

### Stage 6. バッチコンテンツ ✅（dex wave 1 ライブ）

オフラインパイプライン：`content/minds/reviewed/*.json` → `npm run bake:minds` → `lib/minds/baked.ts` に統合し、roster / banter / beats / first-duel / showcase にマージ。  
Wave ツール：`npm run forge:dex`（キュレーション済み名前バンク＋ボイスキット）、`npm run generate:minds`（任意の XAI 下書き）。  
初回手焼き：**STILL**、**KEEL**、**PRISM**、**FABLE**。  
Wave 1 は Gen-1 規模の収集可能セットを上乗せ（`docs/bible/03-champions.md` 参照）。  
ルーキーティアで表現型パーツカタログ＋種族マークを導入し、同じ Force のマインドでも異なる動物として読めるように。マインドごとに新しい GLTF は不要。  
以降の Wave はレビュー済み JSON の追加＋再ベイク＋パーツキット拡張。

## 7. 明示的な非目標

- **第 4 リージョン**。  
  `BiomeConfig` の塊と自然プリセットで安上がりだが、それが罠だ。仕事のない 3 リージョンが、仕事のない 4 リージョンになる。リージョンは兄弟を増やす前に *仕事* を与えられる。
- **Flight-First の感触ゲートを置き換えるもの**。  
  コア動詞がまだ心地よくない状態でリテンション足場を組んでも、可視化された空の順位表ができるだけ。感触の作業は [`flight-first-plan.md`](./flight-first-plan.md) が本資料より優先される。
