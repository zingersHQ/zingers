# ZINGERS 本質と「一つの魂、ネイティブな肉体」原則

> **要約:** Zingers は一つのゲーム、一つの魂を持ちながら、その魂は非常に異なるハードウェア上で*プレイされる*ことを意図している。本書は、この二つの真理を同時に保つ方法を述べる。**魂はどこでも同一**であり、**その魂が纏う肉体はプレイされる部屋に合わせて設計される**。各行動の不変な「魂のアトム」を定義し、今後の全機能が照合されるべき基準を定める。

Version 1.0. 2026年7月

> **方向性ノート（2026年7月、Flight-First）:** 本書はCircuitを通じてこの原則を発見した（「flappy birdはコードベースの中に隠れていた」、§3）。`design-vision.md` v3.0と[`two-doors.md`](./two-doors.md) v2.0はその発見を製品の最上位に位置づけた。**Climb/Ascentはゲームの脊椎と顔であり、五つの動詞の一つではない。** 本書の原則やアトムに変更はない。すでに正しく、Climbを最初に掲げている。以下のClimb行を*他の動詞がぶら下がる要石の動詞*として読み、飛行が他の全動詞をどのように予見するかは[`flyover.md`](./flyover.md)を参照。

[`design-vision.md`](./design-vision.md)（北極星）と[`game-spec.md`](./game-spec.md)（メカニクス）の companion。両者がZingersの*何であるか*を述べるのに対し、本書は「同じZingersが携帯電話からデスクトップへ移行しても生き残る方法」を述べる。携帯電話へのこの原則の具体的で構築可能な適用。モバイルのコアループ、情報アーキテクチャ、各動詞ごとのネイティブな肉体。[`mobile.md`](./mobile.md)に存在する。

## 1. 原則

> **一つの魂、ネイティブな肉体。** アトムはすべてのデバイスで不変。魂が纏う肉体は設計される。ダウンポートでもアップスケールでもなく、プレイヤーの手に持つハードウェアのために。

これは「一つのベース、多くのゲーム」の規律ある形である。クロスプラットフォームゲームを殺してきた二つの失敗モードを拒絶する。

- **ダウンポート**。「モバイルはデスクトップから機能を削ったもの」。携帯電話は不自由で申し訳程度のバージョンを受け取る。（制限）
- **アップフレックス**。「デスクトップはモバイルに光沢を足したもの」。高機能デバイスは薄いモバイルゲームをより良いライティングで着せられる。（無駄）

代わりに、各デバイスは**それ自体で完結したファーストクラスの体験**を得る。そしてそれらはすべて*胸の中に同じ魂*を共有する。携帯電話とノートPCでプレイするプレイヤーは、部屋が運べる複雑さで語られる**一つの**ゲームの中に生きていると感じる。

デバイス間の違いは**主にGPUではない**。**入力の自由度**である。携帯電話は一つの信頼できる精密入力（親指：タップ／ホールド）を提供し、デスクトップは六つ（移動、見る、ジャンプ、スラスト、それらの間のニュアンス）を提供する。「ネイティブな肉体」とは、デバイスが実際に持つ入力のために設計し、そこできれいにすることを意味する。

## 2. 魂のアトム（決して異なってはならないもの）

「一つの魂」をスローガンではなく現実にするため、各コア動詞には**アトム**がある。すべてのデバイスで同一に保たなければならない少数の真理。アトムに含まれないもの（カメラ、自由度、アート密度、所要時間、操作方式）はすべて**肉体**であり、肉体は自由である。異なることを奨励される。

| 動詞 | 魂のアトム（不変、全デバイス共通） | 肉体（デバイスごとに異なることを許す） |
|------|------------------------------------|----------------------------------|
| **Flight** | *上昇*する。高度がスコア。一度の落下でゼロに戻る。ランが**チャンピオンを刻む**。 | 片手親指のホールド→スラスト vs 6自由度自由飛行。2.5D vs フル3D。 |
| **Spectate** | 二つの精神が**明確な勝者**へ議論し、**あなたは結果に利害を持つ**。 | 完全なライブファイト vs 短いハイライト＋勝者予測。6分の観戦 vs 20秒のコール。Flightの下の深さであり、成長の顔ではない（`growth-strategy.md`）。 |
| **Roam** | **Long Vaultの上にある世界に存在**する。手入れし、領有する。 | フル3D自由ローム vs より軽い存在サーフェス。 |
| **Standings** | 客観的で誠実な順位の記録。 | どのように、どこに表示されるか。 |

**新機能のテスト:** そのアトムを一行で述べよ。二つのデバイス版がその一行を共有するなら、それは一つのゲームである。共有しないなら、魂と競合する二つ目のゲームを作ったことになる。そしてgrowth-docの法則が適用される。*チャンピオンへのraise/evolveフックなしに切り離された体験をリリースしてはならない。*

## 3. 具体例。Circuitは我々の「flappy bird」

Flappy Birdをそのアトムまで削ぎ落とすとこうなる。*重力に抗した持続的な上昇。高度がスコア。一度の落下でゼロに戻る。* それは**すでに**Circuit（[`circuit.ts`](./components/grounds/circuit.ts)）である。セクター登頂、深度→時間の順位表、一度の落下でセクター1から再開。ジェットパックは**すでにホールド→スラストのboolean**（[`jetpack.tsx`](./components/grounds/jetpack.tsx)、`flyingRef`）である。垂直軸は*すでに一つの入力*である。flappy birdはコードベースの中に隠れていた。我々はそれを六自由度で包んだだけだ。

ジェットパックは**Trainer専用**（正典：チャンピオンは戦い、Trainerは飛ぶ）なので、Circuitはプレイヤーが「Raise, Don't Fight」の柱を破ることなく自らの手で演じる*唯一の*場所である。それは観客の魂を補完する演者の魂である。

### 二つのネイティブな肉体、一つの魂

| | **モバイルの肉体**（「クール」） | **デスクトップの肉体**（「素晴らしい」） |
|---|---|---|
| 自由度 | 片手親指：ホールド→スラスト、オート前進、ゲートを縫う | 6自由度自由飛行：移動、見る、スラスト、カメラをリード |
| フレーム | 2.5D、レール上、景色が*あなたに*来る | フル3D、*あなたが*景色へのラインを選ぶ |
| 感覚 | 地下鉄即時性、もう一回、もう一回、ragebait | ストリームのショーピース、熟練、ドラマ |
| 設計 | それ自体で完結したゲーム、デモではない | それ自体で完結したゲーム、flexではない |

どちらも他方の残り物ではない。

### ランが*意味する*もの（報酬、魂とCraftで分割）

これによりクロスデバイスの公平性の問題がきれいに解決される。

- **深度は魂 → 共有、クロスデバイス。** 「Long Vaultの上にどれだけ高く登ったか」は**Trainer**についてのロア事実であり、反射神経のベンチマークではない。だから**深度 → Trainer Rank + チャンピオンの体に焼き付けられたFlightシギル**。一つのアイデンティティ、どこでも。
- **時間／熟練はcraft → ネイティブ、デバイスごと。** 片手親指のタイムと6自由度のタイムは正直に同じ列を共有できない（それは一方の肉体を他方の条件に*強いる*ことになる。我々が拒絶する制限）。だから**時間 → Crowns + 別々のモバイル／デスクトップリーダーボード**。

一つの持ち運び可能な*アイデンティティ*記録。二つの正直な*スキル*表現。

### 静かな統合

ゲーム全体の柱#2は**「肉体＝可視化された議論」**である。上昇が*チャンピオンの肉体*にシギル／オーラを刻むなら、その肉体はもはやチャンピオンの議論だけを記録しない。**Trainer自身の登頂**も記録する。*あなたが*手で行う唯一の場所が、主要な柱に折り返される。flappy birdは付録ではなくなり、チャンピオンの自伝のもう一つの文になる。

## 4. レンズの下のゲーム全体

Circuitは原則を発見したレンズであり、原則はすべてを統治する。すべての行がアトムを共有し、すべてのセルはその部屋のために設計される。

| 動詞 | 共有される魂（ベース） | モバイルの肉体 | デスクトップの肉体 |
|------|------------------------|-------------|--------------|
| **Flight** | 上昇、高度＝スコア、一度の落下でリセット、チャンピオンを刻む | 片手親指ジェットパック | 6自由度飛行 |
| **Spectate** | 二つの精神が議論、明確な勝者、あなたは利害を持つ | ハイライトクリップ＋勝者予測 | 完全なライブSSEファイト、可視化された推論、ストリームキット |
| **Roam** | Long Vaultの上にある世界に存在。手入れし、領有する | より軽い存在サーフェス | フル3D自由ローム |
| **Standings** | 客観的で誠実な順位 | コンパクトな順位表＋カード | 完全な順位表、ライバル関係、シーズン |

**決して分岐しないベース:** チャンピオン（キャリア、記憶、戦略、ペルソナ、キャリア由来の肉体）、Five Forces、ロア／IPと用語集語彙、Trainer Rank（永続）、Crowns、Clan忠誠、rating boardの結果。

## 5. 原則が緊張する場所（正直に）

「一つの魂、ネイティブな肉体」は強力な道具だが、魔法の道具ではない。二つの場所で本質的に抵抗し、目を開けて扱わなければならない。

1. **観戦の長さ。** 6分のライブファイトは携帯電話では厳しい売り込みになる。原則が生き残るのは、観戦のアトムを**「コンテストが決着し、あなたは利害を持つ」**と定義する場合*のみ*。「全体を見る」ではない。するとモバイルの正直なネイティブな肉体は**勝者予測＋ハイライトクリップ**であり、デスクトップのそれは**完全なライブファイト**である。これはまさに以前の直感「モバイルではファイトを見ない」と一致する。そしてそれは正しい。*ただし*利害（予測）が魂を保つ場合に限る。観戦時間は肉体。利害を持つことは魂。

2. **「The Grounds Are Alive」vs 軽いモバイルローム。** 設計の柱#4は「純粋なメニューまたはロビーオンリーのゲーム」を排除する。削ぎ落とされた2.5Dモバイルロームは、その柱を正面から違反するリスクがある。解決策：モバイルのローム肉体は依然として**あなたが存在する場所**でなければならない（生きているサーフェス、メニューではない）。より軽いジオメトリ、より少ない自由度だが、リストではない。それを*場所*として保てないなら、「The Grounds Are Alive」はデスクトップ主導の柱であると認め、モバイルには存在の異なる正直な表現を与える。しかしそれは偶然ではなく、意図的に決める。

## 6. これが作るルール（今後の作業のために）

- **アトムを述べよ。** 二つ目のデバイスで機能を作る前に、その一行の魂のアトムを書け。二つのバージョンがそれを共有しないなら、止まれ。
- **ネイティブに設計し、移植するな。** 他のデバイスのビルドからではなく、デバイスの実際の入力（片手親指／6自由度）から始めよ。
- **両方とも完結していなければならない。** どちらのバージョンも他方のデモやflexのように感じさせてはならない。「それ自体で良い」が基準。
- **魂は共有、craftはネイティブ。** アイデンティティ／進行記録（深度、ランク、シギル、チャンピオン）はクロスデバイス。スキルリーダーボードはデバイスファミリーごと。
- **すべてがチャンピオンを刻む。** 切り離されたスコアはない。プレイヤーが手で行うなら、それはキャリア台帳に書き込まれる。さもなくばリリースしない（growth-docの法則）。
